## UI polish round: closer to the 2026-05 design mockup (light sticky-note style)

Design-gap analysis (mock vs device screenshots in .tmp_qa/f*) found four gaps:
[OBJ] placeholder boxes from pasted Apple Notes content, no handwriting voice
for Chinese (Caveat is Latin-only), the home filter-chip row centering its
single chip, and detail pages rendering the derived title as plain Inter body.

### 1. CJK handwriting font (Ma Shan Zheng) — visual voice restored

- Bundled `MaShanZheng-Regular.ttf` (SIL OFL, 5.9 MB,
  assets/fonts/mashanzheng/ + OFL.txt). Registered under its own family AND
  as extra faces inside the `Caveat` family (glyph-coverage selection).
- `AppTextStyles` handwriting styles gained `fontFamilyFallback: ['MaShanZheng']`
  and dropped to w500 (display/title were w600): both fonts are single files
  aliased across weights, so w600 changed nothing for Latin, and the engine's
  per-glyph CJK fallback was observed to skip the fallback family at w600 on
  the Android device. Net effect: Chinese note titles, timestamps and headings
  now render in kai handwriting; digits stay Caveat; zero Latin visual change.
- Verified on device (Note 9): home card titles, "4小时前" timestamps, and
  detail title all kai; AnyNote wordmark unchanged.

### 2. [OBJ] placeholder boxes eliminated (U+FFFC hygiene)

Apple-Notes pastes carry U+FFFC (object replacement) as literal text; Flutter
renders it as a dotted "[OBJ]" box. New display-layer helpers in
note_envelope.dart: `stripObjectPlaceholders`, `sanitizeDeltaOps` (encrypted
content is never rewritten). Applied at every render boundary:

- `plainTextFromStoredContent` / `storedContentToPlainText` (card titles,
  search text)
- NoteRichPreview (card body previews)
- QuillReadOnlyViewer (detail/read views)
- note editor `_loadContentIntoQuill` (edit view; next save persists the
  cleaned delta — self-healing)
- detail title display; detail body strips the derived title line to avoid
  double rendering (see #3)

Device-verified: cards, detail body and editor no longer show [OBJ]; emoji
render normally.

### 3. Detail screen: derived titles now match the cards

Notes saved without an explicit title keep it only as the first content line.
NoteDetailScreen._loadNote now derives the title from the body's first line
(mirroring NoteCard) when the stored title is empty, and
`_stripFirstLineFromBody` removes that line from the viewer content. Detail
titles render in the handwriting voice and are not duplicated.

### 4. Filter chips row left-aligned

The body Column's default centered crossAxisAlignment made a lone "All" chip
float center. `_buildFilterChips` now fills the width; the row hugs the left
edge like the mockup.

### 5. Dark-mode sticky-note color identity

Grid cards in dark mode now blend the pastel over darkCardBg (alpha 46) with
dimmed pastel borders, so per-note color identity survives dark mode while
staying muted (mockup is light mode).

## UI polish round 2: skeuomorphic sticky-note paper cards

User feedback: the mockup's sticky notes are skeuomorphic (real paper on a
desk); the cards were still flat tinted rectangles. Sampled the mockup
pixels and extracted the signature cues, then implemented them:

1. **Saturated paper palette** (`AppColors.notePapers`, sampled from the
   mock): paperYellow #FBE48E, paperWhite #F9F4EA, paperPink #FDD0CB,
   paperLavender #E4D3F6, paperCream #FCF7EA, paperGreen #E2EFD0. Light-mode
   grid cards now use the paper color directly (no white alphaBlend, no
   border — the color block + shadow define the sheet edge).
2. **Random tilt**: each card rotates by a deterministic ±~1.2° cycle
   (`_paperTilts` by listIndex) inside `Transform.rotate` — the
   hand-placed feel. Grid layout only; list rows stay straight.
3. **Realistic shadow** (`AppShadows.paperOf`): two layers — tight contact
   shadow + warm diffuse (offset 3,6 blur 16, warm brown ink) — light mode
   warm, dark mode soft black. Radius dropped 20 → 12 (real Post-it).
4. **Corner doodles**: footer is now timestamp bottom-left + a small
   hand-drawn-style emoji sticker bottom-right (⭐📖💡🌱💛✨📌🎵 cycled by
   note id hash, 75% opacity), matching the mock's sketches.
5. **Desk background**: notes home scaffold uses `lightDeskBg` #F2EFE9 in
   light mode so the paper pops (mockup's page bg is deeper than the card
   paper). Dark mode unchanged.

User-picked note colors now map to the saturated paper set
(`_pastelColors` keyword table).

## Round 4: paper aesthetic promoted to design-system infrastructure

User direction: stop replicating the mock screen-by-screen; extract its
theme into AnyNote's foundation so any surface can be "a piece of paper".

### New infrastructure

1. **`core/theme/paper_tokens.dart` — `PaperTokens` ThemeExtension**
   Semantic tokens: `papers` (saturated tone cycle), `desk` (surface behind
   sheets), `ink` / `inkMuted` / `inkDoodle` (writing on paper), dark-mode
   `darkWashBase`+alpha, `tilts` cycle, sticky `radius` (12). Constants
   live as `PaperTokens.light` / `.dark`, registered in all four themes
   (high-contrast included) via `extensions:`; `PaperTokens.of(context)`
   resolves per brightness with a safe fallback. `toneFor(index,
   brightness)` / `tiltFor(index)` give deterministic per-item values;
   `lerp` supports theme transitions.
2. **`core/widgets/paper_surface.dart` — `PaperSurface`** — the reusable
   sheet: tone cycle or explicit override, tilt on/off, Post-it radius,
   `AppShadows.paperOf`, optional periwinkle selection ring, optional
   corner doodle (`showDoodle`), dark hairline. Presentational (no
   gesture/semantics opinions) so callers keep their own interaction.
3. **`core/widgets/paper_doodle.dart`** — `PaperDoodle` + `PaperDoodleKind`
   moved out of notes into the design system; `PaperDoodleKindX.forSeed`
   replaces ad-hoc hashing.

### Consumers migrated (visuals unchanged, verified on device)

- NoteCard grid = `PaperSurface` + tokens (tone overrides for user-picked
  colors and photo-paper cards remain note-domain logic).
- NoteCard title/timestamp/doodle inks now come from `paper.ink*`.
- Notes home Scaffold background = `paper.desk`.

## Image embeds disappearing — root cause chain fixed (ce43d5e)

Device repro (Note 9, debug build): notes with images showed them on home
cards but never in detail/editor. Forensics via adb DB pull + instrumented
viewer logging surfaced three independent loss paths, all fixed:

1. **Sync push downgraded rich notes (root cause).** `_encryptNoteForPush`
   packed `plainContent` (plain-text projection, embeds -> U+FFFC) into the
   envelope; the next pull applied that blob (LWW remote-wins after push)
   and overwrote the local Delta JSON — images permanently stripped from
   every synced note. Push now decrypts `encryptedContent` and packs the
   authoritative body. Pull derives the plain projection via
   `plainTextFromStoredContent` for FTS/cards and populates
   `firstImagePath` (was silently nulled by `updateNote`).
2. **Whole-note AI polish/translate deleted embeds.** `_replaceSelectedOrAllText`
   cleared the document before inserting the text-only LLM reply. Now
   collects embeds first and re-appends each on its own block at the end
   (`doc.insert(len-1, '\n')` then embed before the final break — insert at
   `doc.length` trips a QuillContainer assertion).
3. **Detail title derivation dropped embeds.** `_stripFirstLineFromBody`
   discarded embed ops before the first line break and could emit a Delta
   without a trailing newline (Document.fromJson rejects it -> raw-JSON
   fallback text). Embeds kept in all positions; stripped Delta gets a
   terminating newline op.
