# 技术实施方案 — 产品设计优化（2026-11）

> 配套评审：`design-review-2026-11.md`（问题、证据、评分）。产品记录：仓库根
> `PRODUCT.md`。方向于 2026-11-24 确认：**放大个性**（纸张 / 便签 / 手写）；
> 顺序是**先做图标和动效系统，再逐页应用**；图标族 **Phosphor 线框**；
> 动效**更有表现力**（接受打开页面时多等一小会儿）。

---

## 1. 现状（main @ 3d6d990）

- **图标三族混用**：`AppIcons` 有 121 个名字，但全库只有 242 处用它；
  另有 **677 处直接写 `Icons.xxx`**（259 个不同的 Material 图标，114 个文件），
  测试里另有 88 种。三星 Note 9 上部分 Material 码位被系统画成彩色 emoji。
- **动效各定各的**：动画点共 36 处（27 处隐式动画 + 9 个 `AnimationController`），
  时长取自 `AppDurations`、`AppAnimation` 和字面量三个来源，曲线 9 种。
- **"减少动画"只管住了路由转场**：开关是内存里的 `StateProvider`，重启即失效；
  Flutter 自己的动画（底部面板、菜单、开关、隐式动画）只认**系统级**开关
  （`AnimationController` 读 binding 的 `disableAnimations`，为真时把时长压到 5%）。
- 入场编排：便签逐张 250ms + 30ms 错峰；设置页分组 50ms × 最多 11 组
  ——进页面最长要等 750ms 才看全。

## 2. 目标

1. 全库只剩一个图标族，一律经 `AppIcons`；以后混不进第二个族（有测试守着）。
2. 一套动效令牌（四个时长、两条曲线、两个弹簧），36 个动画点全部走它。
3. "减少动画"开关对**整个应用**生效并持久化，行为与系统开关一致。
4. 四个属于纸张世界的动效：便签落位、掀页、按压、保存落地。
5. 去掉纯装饰的入场编排；每屏布局不变。

## 3. 设计

### 3.1 图标规则（`frontend/lib/core/theme/app_icons.dart`）

- **名字表达含义**（`delete`），不表达形状（`trash`）。
- **默认 Regular（线框）**。`…Filled` 只表示开关的"开"态（星标 / 图钉 / 书签 /
  录音 / 朗读 / 高亮…），必须与同名 Regular 成对出现，不做装饰用。
- **Bold 只出现两次**：高对比度主题的浅色 / 深色选项——"笔画更粗"本身在表达
  "对比更强"。
- Material → Phosphor 的取舍原则：填充 / 线框 / 圆角变体合并为同一个名字；
  表示选中态的填充变体映射为 `…Filled`；Material 里语义相近的合并
  （`label` / `sell` / `label_outline` → `tag`，`translate` → `language`）。
- 对照表里 Phosphor 没有对应字形的，按含义另选：`schedule` 是时钟（原表错指成
  日历）、`quote` 是引号（原表错指成 "Aa"）、`publish` 是纸飞机、`style` 是羽毛。

**守卫**（`test/design/icon_system_test.dart`）：
① `lib/` 里不得出现 `Icons.x` 或任何直接的 `PhosphorIcons…` / `PhosphorIcon`；
② 每个 `…Filled` 都有同字形的 Regular 配对；③ Fill 只用于 `…Filled` 结尾的名字；
④ Bold 只用于 `highContrast*`。

### 3.2 动效令牌（`AppAnimation`）

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `fast` | 120ms | 按压回弹、开关、箭头转向、文字切换 |
| `standard` | 220ms | 底部面板、卡片落位、标签页切换、淡入淡出 |
| `emphasized` | 320ms | 页面推入 / 返回 |
| `expressive` | 480ms | 标志性动作（便签落定） |

曲线只有两条：`arrive`（到位：强调减速，进入 / 落位）、`depart`（离开：强调加速）。
弹簧两个：`press`（临界阻尼，压下去不回弹）、`settle`（轻微欠阻尼，松开后落定）。
"纸张落下时那一小下过冲"由弹簧给出，不新增曲线。

`AppDurations` 只留非动画时长（防抖、自动保存延迟等）；带 `Animation` 字样的常量删除。

### 3.3 "减少动画"如何对整个应用生效

三层，各管一段：

1. **全局杠杆（Flutter 自己的动画 + 所有隐式动画）**。`AnimationController`
   读的是 binding 上的 `disableAnimations`。应用改用自己的 binding
   （`AppBinding extends WidgetsFlutterBinding with ReduceMotionBinding`），
   把应用内开关的值并入这个 getter。效果：开关打开后，凡是按时长驱动的动画
   都按系统级"移除动画"的同一规则处理（压到 5%，一帧内到位）——底部面板、
   弹出菜单、开关、水波纹、27 处隐式动画，全部覆盖，无需逐个改写。
   进度指示器这类"动画本身在传达状态"的（`AnimationBehavior.preserve`）保持不动。
2. **`context.motion`（我们自己写的编排）**。时长解决不了的东西要显式判断：
   错峰延迟、循环（同步图标旋转、骨架屏）、弹簧、页面转场的形状。
   `AnimationConfig.of(context)` 提供 `fast / standard / emphasized / expressive`
   与 `arrive / depart`，减少动画时为 0 / linear。
3. **开关持久化**。`reduceMotionOverrideProvider` 改为 `StateNotifierProvider`，
   存 SharedPreferences（`reduce_motion`：`system` / `on` / `off`），与主题选项同一模式。

减少动画时的转场不是"闪一下"：页面切换退化为 120ms 的纯淡入（不动、不缩放）。

### 3.4 四个纸张动效

| 动效 | 发生在 | 做法 |
| --- | --- | --- |
| **掀页**（标志性动作） | 打开一篇笔记 / 进入子页 | 新页从下方 24px、0.96 倍带阴影升起；底下那页变暗到 92%、缩到 0.985——像一张纸被掀起来放到桌上。`emphasized` + `arrive`。返回反向。 |
| **便签落位** | 首屏便签出现 | 卡片从 1.04 倍、带一点自身纸色倾角落到位，`standard` + `settle`；错峰 24ms，最多 8 张（首屏）。滚动加载的卡片直接出现。 |
| **按压** | 卡片 / 按钮按下 | `PressableScale`：压到 0.97（`press` 弹簧），松开落定（`settle`）。 |
| **保存落地** | 编辑器"已保存" | 对勾从上方 3px、1.25 倍落定——像盖了个章。`fast`。 |

**去掉的编排**：设置、LLM 配置、导入、加密、平台连接页的分组错峰入场（50ms × N）
→ 直接出现；空状态的 400ms 回弹 → `standard` 淡入。

## 4. 不做的事（本期）

- 不改任何一屏的布局、颜色、字号、信息架构（留给后续阶段逐页做）。
- 不收敛组件（47 处裸 `showModalBottomSheet`、11 套空状态等）——那是下一个系统层。
- 不做 iOS 真机验证（iOS 构建无签名）；iOS 保持系统自带的转场。

## 阶段 2 — 首页与编辑器（2026-11-25）

> 方向由用户在 2026-11-25 确认：**采用评审建议**——卡片以可扫读为先，手写只留给标题。
> 这与"放大个性"并不相反：个性留在纸色、倾斜、手写标题和墨迹涂鸦上，
> 正文与时间回到界面字体，让一张便签在一瞥之内读得完。

### 范围

**便签卡片（评审 P1）**

- 标题：手写，网格里最多 2 行（原 4 行），超出省略。
- 正文预览：界面字体（Inter），13px，最多 4 行；不再是手写体。
- 时间戳：界面字体 13px / 500；不再是手写体。
- 预览不把位置让给空行（**实施中补上的**）：看画廊时发现，段落之间的空行被原样画进预览，
  4 行里常有 1–2 行是空白——"三亚旅行清单"那张卡只露出两行有字的内容。卡片是为了找到笔记，
  预览里去掉空行，把行数留给有字的部分；点开后的正文排版不变。纯文本与富文本（Delta）两条路径都改。
- 墨色：时间戳的墨色按纸色取——沿用纸的色相、压暗到对比度 ≥ 5:1（六种纸各一个）。
  原来六张纸共用一个暖灰，只有 2.2–2.9:1。深色主题同理：洗色底上的时间戳 2.87:1、
  预览 4.4:1，分别提到 ≥ 4.6。

**颜色令牌（评审 P2 "对比度"中与首页、编辑器有关的部分，全局生效）**

| 令牌 | 现值 | 新值 | 依据 |
| --- | --- | --- | --- |
| `primary` | #8B7CE8 | #6B5CD0 | 白字 5.16、作文字压纸面 4.87（原 3.42 / 3.22） |
| `primaryDark` | #7466D6 | 比新 primary 再深一档 | 按压态 |
| `lightTextTertiary` | #9C8F83 | #7B6A59 | 纸面 4.89、输入框 4.65（原 2.97 / 2.82） |
| `darkTextSecondary` | #C4C0E0 | #CAC5DA | 洗色底上最低 4.62（原 4.42） |
| 状态墨色（新） | — | 成功 / 警告 / 错误各一对（浅、深） | 浅色 ≥ 4.6、深色 ≥ 4.6 |

- 状态色为什么新增而不改旧的：`AppColors.success` 等是浅深两个主题共用的常量，
  而同一个颜色不可能在浅色纸面和深色 navy 上同时达到 4.5:1。旧的三个常量保持不变
  （它们还作填充色用，共 130 多处），新增 `statusSuccessInk` 等六个别名给**文字和图标**用；
  本阶段只把首页与编辑器上的用法换过去，其余页面留给"对比度与阴影"那一步。
- 品牌紫加深是可见的变化（按钮、悬浮按钮、导航选中态都会深一点）。评审给的两个选项是
  "加深或换深色文字"；选加深，是因为深色主题里已经是"浅紫底 + 深色字"，浅色主题再用深色字
  会让两个主题的主按钮变成两种做法。

**编辑器 / 详情页**

- 详情页顶栏的铅笔图标改为带文字的"编辑"按钮（评审："顶栏铅笔是什么意思？"）。
- 首页悬浮按钮加上便签同款的暖色接触阴影（终审："悬浮按钮是平的"）。
- 定稿包在真机上逐页看过之后又补了三处（**都是看了才发现的**）：
  - 首页菜单的排序项：阶段 1 给当前项加了对勾之后，那一行的标题折成"…（最" / "新）"。
    第一次修错了——给六行都留对勾位，结果四行全部折行（真机上才看到）。真正的原因是 Flutter 的 `ListTile`
    在向菜单报告行宽时不计"尾部控件前面的间距"，所以只要用了尾部控件，菜单就比需要的窄。
    现在对勾并进标题那一行（文字 + 间距 + 对勾位），行宽报得准，六行都在一行内；测试断言"最长的那条标签只有一行高"。
  - 只有标题的笔记，卡片里留着一道空行：预览没有内容时仍然排了一段。现在空预览不占高度。
  - 系统导航栏跟着**应用**的主题走（**老问题，不是这次引入的**）：`main.dart` 用的是系统的深浅，
    所以"系统浅色 + 应用深色"时屏幕底下留着一条白色的导航栏。
- "已保存""未同步"改用状态墨色。
- 编辑器顶栏的"保存并关闭"从光秃秃的对勾改为带文字的"✓ 完成"（**真机上看到后补上的**）：
  它紧挨着"已保存"的状态对勾，一绿一紫两个对勾并排，读起来像两盏状态灯。沿用已有的 `done` 文案，没有新增字符串。
- 编辑器顶栏的三个状态统一墨色（**实施中补上的**）：保存中的转圈原用 Material 从种子色推导出的 `tertiary`，
  不在调色板里；未保存的红点原用 Material 默认的 error。现在转圈用主题的二级文字色（"在进行中"，不抢眼），
  红点用错误状态墨色。

**本阶段不做**（记入后续）：深色主题的六种便签色几乎同一种灰、列表视图没有纸色、
`shadowLight`/`shadowMedium` 的 alpha 笔误（修好后十几个页面会同时出现边框和阴影，需要逐处取舍）、
编辑器溢出菜单的分组、"减少动画"回到"跟随系统"。

### 测试

- 预览：空行不占行——纯文本与 Delta 各一条用例；空行后的第一行正文要露出来。

  真机启动一次（`app_system_bars_test.dart`）断言"系统浅色 + 应用深色"时导航栏是深色。

**过程中出的错**

1. **接手时的编译错误。** 上一轮会话修到一半中断，工作区里留着 `plain.trimRight('\n')`——Dart 的 `trimRight` 不接受参数。
   连带 23 个测试编译失败。
2. **第一个修复让全量测试挂死。** 我改成"逐个删掉文档末尾的换行"，而 Quill 的删除规则在删除触到文档末尾时会补回一个换行：
   循环永远结束不了。它是同步死循环，测试框架的超时也救不了，挂了二十多分钟才发现。改成在构造文档之前裁剪 Delta。
3. **第一次格式检查是空的。** 容器没挂 pub 缓存卷，格式化工具读不到 lint 配置、输出为空，于是每个文件都显示"整份都有差异"。
4. **悬浮按钮的长按在真机上不工作**（提交 `eefadf3` 装上手机后才发现）。外层 `GestureDetector` 的 `onLongPress` 从来没触发，
   长按直接进了新建笔记。原因：`FloatingActionButton` 自带的 Tooltip 也在监听长按，而且它在里层，总是先一步赢下手势。
   本地 3,447 个测试是绿的——没有一个是"按住不放"的。修法：把这个提示条改成"手动触发"（无障碍标签照旧），
   并补一条"按住悬浮按钮要出现底部面板"的测试；把提示条改回去，这条测试的报错和真机现象一致。
5. 本地画廊的编辑器渲染里有一条红色横幅（`type 'Null' is not a subtype of type 'bool'`）。这一轮之前就在，
   只出现在画廊（真机上没有），是渲染工具自身的问题，没有处理。看画廊里的编辑器截图时要知道这一点。

6. **菜单底边的渐隐来得太晚。** 独立终审对真机抓屏的判定把这一条扣下了：深色下编辑器菜单的那张抓屏（`r3-20`，
   打开菜单 1.5 秒后拍的）最后一行仍是实色被切。我上手机重拍：等 2.5 秒、键盘收起或开着，渐隐都在。所以那张图拍早了——
   但"拍早了"正是问题：渐隐原先按菜单上一次滚动时的位置摆放，只能等菜单完全打开再淡入，在这台手机上是一个多秒。
   改成绘制时实时取菜单此刻的位置（同一帧里菜单先布局完、渐隐再画），从菜单出现的第一帧就在，键盘收起时也跟得上。
   顺带让两个长菜单把行裁剪进圆角（原先没裁，被切的行会在圆角外露出一小块）。
7. **向手机发了一串没有逐个确认前台的按键。** 11:25 左右，我要在测试账号里建一条"两段正文"的笔记给终审看。
   点编辑框之前确认过 AnyNote 在前台，随后那一串删除、文字、回车是直接发的；发的时候前台已经是系统设置（Wi-Fi → 通知），
   手机的主人正在用。发现后立刻停手。不知道那些按键有没有改动设置页里的东西。那条两段式笔记没有建成；
   测试账号里留下了一条 16 个字符的草稿"QA two pQA two p"，等手机空出来再删。

    测试读的是那个区域的属性值。可系统取的是"每一帧屏幕最上方最靠上的那一个标注区域"，而页面自己的 AppBar
    也带一个，比根部深一层——面板和遮罩不带，于是往下找到的是 AppBar 的（深色图标）。`7cb01de` 把样式挪到
    盖住整个应用的最上一层；测试改成断言系统实际拿到的样式（`SystemChrome.latestStyle`），
    并把区域挪离屏幕顶部做了一次突变——报错和手机上的现象一致。
12. **浅色下状态栏图标的颜色，我差点按纯白去估。** `7cb01de` 上手机后图标确实变浅了。我量的是图标区域的平均色，按它算出 25% 的暗条
    就能到 5.5:1。改用量时钟笔画的主色，才看到这台手机把"浅色图标"画成 `#DBDBDA`（约 86% 的白），压在 `#737270` 上只有 3.46:1，
    25% 的暗条到不了 4.5:1。构建之前把暗条加到 30%（`ea836ec`），手机上实测 5.34:1。教训：对比度要拿最小那个元素的实际墨色去算，
    不能拿一块区域的平均色。

拍"保存中 / 未保存"两个状态时，我把一条富文本笔记切到了纯文本模式，文本框里显示的是**这条笔记的原始 JSON**
（`[{"insert":"Search Target Note XYZ\n…"}]`），状态栏按这段 JSON 计数（102 个字符、1 行），上面还写着"已保存"。
在纯文本模式下写一句话再切回去，笔记就成了"JSON 文本 + 那句话"。查代码确认了三件事，都修了：

- 纯文本编辑器拿的是存储内容的原文（富文本笔记就是它的 Delta JSON）。现在拿的是笔记的文字：Delta 的文字，去掉文档末尾那个
  不属于笔记的换行；图片写成编辑器本来就会还原成图片的 Markdown 图片语法。
- 切换模式时两个编辑器之间不携带文本：富文本里写的内容不在纯文本里，纯文本里写的也不在富文本文档里，下一次保存就丢了。
  现在双向携带；纯文本里没改动就切回去的，富文本文档原样恢复（格式和内嵌都在）。编辑器在笔记之间切换时保留当前模式，
  停在纯文本模式时打开另一条笔记也是同样的处理。
- 打开笔记就会保存一次：载入时往控制器里放文本触发了"内容已变"的监听——每次打开都多两个版本快照、更新时间被改、再同步一次。
  现在载入不算编辑。
